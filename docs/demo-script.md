# 演示脚本:多 Agent 跨境电商运营台(双幕:演练 dev → 生产 prod)

> **形态**:局域网部署 · 单端口同源(`<主机>:3000`,前端 + API + WS)
> **时长**:约 15-20 分钟(含一次切幕,30-60s)
> **素材**(2026-09-13 试运行库):3 条影子段(SYN-KB-477 / SYN-CA-478 / SYN-TL-480)+ 1 条 prod 待批(SYN-TL-190 热熔胶枪下架)
> **核心话术**:对话即操作——Manager 规划切片、业务 Agent 执行、**对外动作经审批护栏落地**;演练剖面先影子后补执行,生产剖面审批锁死。

---

## 0. 会前检查(演示前 10 分钟)

- [ ] `docker compose ps` 十服务全 healthy(尤其 app / postgres / redis)
- [ ] `curl -s localhost:3000/health` → `"environment":"dev"`
- [ ] 浏览器打开 `http://localhost:3000`(或 `127.0.0.1:3000`——两者均已入 CORS 白名单),登录 `admin`
- [ ] 审批中心核对:**待批 1 + 影子 3**
- [ ] **红线**:演示前勿跑在线测试(`uv run pytest` 的 e2e/integration 与前端 e2e 会直写 dev 库);演示当天勿启 `--profile sim`

## 1. 第一幕:演练剖面(dev)——默认启动态

### 1.1 开场 · 驾驶舱(~1 min)

- 页面:驾驶舱 —— 协作管线卡片(选品分析 / 订单管理)+ 任务输入框
- 话术:「下达一句话需求,Manager 拆成切片计划,按依赖扇出给业务 Agent;对外可见的动作(上下架/改价/删单)**不会立刻生效**,先登记待人工决定。」

### 1.2 审批中心 · 影子段 + 补执行(核心卖点 1,~3 min)

- 页面:审批中心 —— 顶部「待批 1 / 影子 3 / 实时通道已连接」
- 展示任务卡:原始需求 + **切片计划预览**(每步描述 + 序号,「本批」标出当前段)+ Agent 执行报告
- 话术:「演练剖面(dev)下,高危建议**不阻断流程**,登记为**影子段**——模拟登记、不生效;由人工一键**补执行**放行。」
- **动作**:点其中 1 条(如「无钉订书机…」旁)的「**补执行**」按钮
- **预期**:影子计数 3→2、该卡消失(留下 1-2 条给下次演示亦可)
- **核验**:切数据台搜该 SKU → 状态 `draft → active`;任务时间线新出通知/事件

### 1.3 数据台(~1 min)

- 页面:数据台 —— 「共 500 件」;搜「露营椅」→ 共 4 件(演示搜索/筛选)
- 话术:「商品与订单是**纯只读**数据面,任何变更只能走对话 + 审批。」

### 1.4 起草工作台 · 商品查证(核心卖点 2,~2 min)

- 页面:起草工作台;语言选「中文」
- **动作**:粘贴提问 —— `你好,请问这个折叠露营椅还有货吗?大概什么时候能发货?`
- 等 ~25s(LLM 查证 + 起草):
  - **查证证据**块:4 款折叠露营椅(SKU / 价格 / 各币种 / 库存 / 状态)
  - **回复草稿**:逐款库存 + 无法确认发货时效的如实说明 + 澄清请求;可编辑、一键复制
- 话术:「草稿**不落库、不进审批**;先查证后起草——消息里的商品指代必须可核验,查不到就不编。」

### 1.5 驾驶舱收尾 · 报表 + 汇率卡片(~1 min)

- 近 7 日成交额(CNY)、订单七态分布、低库存清单
- 汇率卡片:当期 `1 USD = 6.73 CNY` + **近 7 日走势**(订单快照按日取末笔,7 个成交日)
- 话术:「汇率快照随订单落库——成交金额可比、可审计。」

## 2. 切幕:dev → prod(30-60s)

```bash
ENVIRONMENT=prod docker compose up -d app
curl -s localhost:3000/health        # 期望 "environment":"prod"
```

- 容器会重建并**可能重装一次依赖**(uv sync,网络不佳时更慢)——用话术填充:「同一套系统切到生产剖面:影子段自动隐藏、补执行端点关闭,审批**锁死**。」
- 切完**刷新浏览器**。

## 3. 第二幕:生产剖面(prod)

### 3.1 审批中心 · 剖面过滤 + 待批单(核心卖点 3,~3 min)

- 页面:审批中心 —— **影子段全部消失**(剖面过滤,前端零感知),只剩「待批 1」热熔胶枪卡
- 展示:动作(下架商品)、现状(在售 → 已下架)、备注框、切片计划旁挂
- **动作**:点「**批准**」→ 按钮变「提交本任务决定」→ 点提交
- 等 ~30s(图恢复执行):卡片消失、待批 0
- **核验**:数据台搜 `SYN-TL-190` → `active → inactive`(下架生效)

### 3.2 收尾话术

- 「演示里 Agent 的一切对外动作——上架、下架、改价、删单——都经人工批准才落地;批次、决定人、备注全程可追溯。」

## 4. 回退(演示结束后)

```bash
docker compose up -d app            # 回 dev 剖面
```

## 5. 再演复位(下次演示前)

素材消耗后按此重建(选**无未完成订单**的商品,避免 Agent 前置校验拦下):

```bash
# dev 下补影子段(会产生新 shadow 批次;选 draft 商品)
printf '%s' '{"request":"把草稿商品 SYN-XXX 上架","session_id":"trial-seed"}' > /tmp/t.json
# → POST /api/tasks(--data-binary @/tmp/t.json,带 Bearer token)

# prod 下补待批单(切 prod 后)
printf '%s' '{"request":"把商品 SYN-XXX 下架","session_id":"trial-seed"}' > /tmp/t.json
# → 期望 {"status":"interrupted"};随后切回 dev
```

## 6. 注意事项与已知边界

| 事项 | 说明 |
|---|---|
| **第一幕勿点待批卡** | 待批单(商品 190)是第二幕素材——issue #40 修复后,跨剖面决定**会真实生效**(旧「静默无效 / 批次僵尸化」已修),第一幕误点即提前消耗;批准动作留给第二幕(prod)演示 |
| **下架/挂起类任务选无订单商品** | 有未完成订单的商品,Agent 的切片描述含「确认无依赖后执行」,LLM 会主动拦下不登记(实证 3 连败) |
| **审批动作不产生铃铛通知** | 通知效果仅订单状态 / 库存低 / 汇率缺失三类;演示铃铛需走订单流转类动作 |
| **`127.0.0.1` ≠ `localhost`** | 未列入 `CORS_ORIGINS` 的 origin 握手 400(现象:页面能开、实时通道不动);局域网地址已入白名单 |
| 库内历史痕迹 | 商品 95/190 inactive、479 active 为彩排/历史产物,不影响演示 |
| **本机演示优先** | 统一用 `localhost:3000` 或 `127.0.0.1:3000`(两者均已入白名单,握手实测 200);局域网多设备实访**暂缓**(防火墙入站 tcp 3000 未验,日后要演再补测) |
