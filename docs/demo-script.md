# 演示脚本:一台便携咖啡机的旅行(从选品到售后)

> 面向技术面试官 / 同行的 5–8 分钟录屏脚本。主题:「多 Agent 协作 + 事件驱动 + 人机混合」的完整业务闭环。
> 环境:本地 `docker compose up -d` + Ollama(bge-m3)+ 后端 :3000 + 前端 :5173,数据已 seed。

## 场景 0:驾驶舱总览(30s)

- 打开 `http://localhost:5173`,默认「驾驶舱」视图
- 口播:「这是三个 Agent —— 选品分析、订单处理、智能客服。右侧是实时事件流,所有跨 Agent 协作都在这里以事件形式可见。」
- 截图点:三 Agent 卡片 + 实时事件流

## 场景 1:选品(90s)

- 在右侧聊天面板输入:「帮我分析便携咖啡机在美国市场的选品机会」
- 观察:Agent 卡片变 busy → 事件流依次出现 `task.assigned` → `report.generated`
- 展开回复下方的步骤时间线(「共 N 步 · 4 个工具调用 ▸」)
- 口播:「选品 Agent 自主完成了趋势查询 → 竞品分析 → 评分 → 报告生成,图谱强制它按流程走。报告完成时发出了 `report.generated` 事件——注意这个事件,它是整个闭环的起点。」
- 截图点:Markdown 报告渲染 + 展开的步骤时间线 + 事件流

## 场景 2:自动商品草稿(60s)

- 切到「商品商店」视图,口播:「订单 Agent 订阅了 `report.generated`,已经自动把报告里的咖啡机提炼成商品草稿了。」
- 搜索/滚动找到「便携咖啡机」卡片(状态草稿,无立即购买按钮)
- 切回驾驶舱,在聊天输入:「把便携咖啡机商品创建成正式商品并上架」
- 观察:事件流 `product.created` → `product.updated`;商店页刷新出现可购买卡片
- 截图点:商店页咖啡机卡片(上架前后对比)
- 口播(可选):「这一步也演示了事件驱动的前端刷新——商品事件实时更新商店页。」

## 场景 3:买家购买(60s)

- 商店页「立即购买」→ 自动切「我的订单」
- 口播:「演示买家张伟直接下单,订单以 pending 状态创建,由 REST 直下;同时客服 Agent 收到 `order.status_changed` 事件。」
- 截图点:订单卡(待确认徽标)

## 场景 4:订单流转 + 主动通知(90s)

- 切回驾驶舱聊天,输入:「把订单 A100 确认并发货」(用真实订单号)
- 观察:事件流订单状态流转 ×2;聊天面板弹出**客服 Agent 主动通知**淡黄气泡(「您的订单已确认/已发货」)
- 切「我的订单」看状态徽标变为已发货
- 口播:「订单 Agent 负责状态机流转;客服 Agent 订阅状态事件,主动给买家发通知——买家没有说话,客服先来关怀。」
- 截图点:主动通知气泡 + 订单页紫徽标对比

## 场景 5:库存告警(45s,可砍)

- 聊天输入:「检查便携咖啡机库存,当前 10 件,安全线 100」
- 观察:`inventory.alert`(红点事件)→ 客服通知气泡
- 口播:「库存告警同样经事件总线流转到买家侧。」

## 场景 6:售后(90s)

- 切「客服中心」,输入:「我的咖啡机物流太慢了,我要退货!」
- 观察:客服工作流第一阶段强制 sentiment_analysis + faq_search;步骤时间线可见
- 回复触发 FAQ 模板填充(`reply.generated`),若情感为负且未解决则 `escalate_ticket` 升级(`escalation.triggered`)
- 口播:「客服的工作流是图级强制的——必须先分析情绪、查 FAQ,才能回答;无法解决时升级人工。」
- 截图点:售后对话 + 步骤时间线全貌

## 场景 7:多语言(30s,加分镜头)

- 客服中心输入:「How long does shipping take?」
- 观察:faq_search + translate 多语言回复
- 口播:「客服支持多语言,FAQ 按语言检索。」

## 场景 8:收尾(30s)

- 口播重点(可配合 psql 展示):
  1. 事件总线:12 类领域事件,工具 emit → Agent 订阅 → WS 桥接
  2. 任务审计:`agent_tasks` 表记录了每次任务(psql: `select * from agent_tasks order by "createdAt" desc limit 5`)
  3. 聊天记录持久化:`conversations` 表
  4. 同步 LLM 调用经 `asyncio.to_thread` 卸载出事件循环(任务执行期间其他请求不阻塞)
  5. 契约真源 `frontend/src/types/events.ts`,前后端契约测试锚定

## 失败预案

| 风险 | 预案 |
|------|------|
| LLM 不按预期调工具 | 台词用命令式(「把订单 xxx 发货」);重试一次(Redis 缓存 300s 可复现) |
| 选品报告太长 | 步骤时间线默认折叠,展开以截图为准 |
| DeepSeek 限流 | 提前彩排一遍;备选台词:「查一下 FAQ 里退货政策是什么」 |
| 库存场景被砍 | 跳过场景 5,口播一句带过 |

> 注意:Windows 下用 python 脚本发 REST 请求(内联 curl 中文 JSON 会损坏)。
