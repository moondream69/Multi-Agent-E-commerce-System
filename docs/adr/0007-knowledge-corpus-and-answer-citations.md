# 知识库语料供给与答案引用增强

## 背景

2026-09-13 完成度审计后的定向核查发现:**检索语料在新系统中空置且无供给路径**。实测三项:PG 的 `faq` / `market_intel` 两表 0 行;Milvus 两集合 `rowCount = 0`;全代码库**无任何写入调用者**——`VectorRepository.upsert` 抽象在、实现带契约测试,但没有一个调用点。

对照 ADR-0005:正文把「当前量级 ≈350 条×1024 维」当作**既存前提**来论证 Milvus 选型,而该语料来自旧系统 `seed.py`(商品 150 + FAQ 100 + 情报 100 = 350,LLM 生成式 + 向量化),重建时被整体丢弃、无替代。后果是 **A3(选品四步走通)与 A10(faq_search 可用)退化为"链路走得通、内容空转"**——`trend_query` / `competitor_analysis` / `faq_search` 三工具恒返空命中,报告与草稿无检索依据。

本条 ADR 由两件事共同触发:①为 Agent 评测线(#45)补语料地基——没有非空语料,"报告是否基于证据作答"这条判据不可证伪;②把检索能力从「工具返回原始 hits、由模型自行阅读」升级为「答案携带可点开的出处引用」。

**业务三域版图不变**(选品/订单/客服三业务 Agent 不扩展);本 ADR 修订 ADR-0005 的语料量级陈述与前端能力描述。

## 决策

### 语料供给

- **市场情报走真实公开报告**,英文优先、条款干净者(已实测直链可下载的材料);中文侧**仅收平台官方主动发放的白皮书**。**明确拒绝**条款严苛的中文源(付费墙、禁止复制传播、禁止商业用途三类)。
- **FAQ 走自造高保真**。侦察已确认公开渠道**不存在**「买家问 → 卖家客服答」方向的语料——可得材料全部是「卖家问 → 平台/服务商答」。自造流程:LLM 生成候选 → 人工筛选修订 → **冻结成语料文件入仓**;生成只发生一次,冻结后评测基准锚得住。
- 主题与规模沿用旧系统划分(该划分已被宪章背书):FAQ 七主题(物流配送 / 退货退款 / 支付方式 / 关税清关 / 质量真伪 / 尺码适配 / 售后保修)+ 市场情报四类(趋势分析 / 竞品分析 / 季节性规律 / 行业洞察),约 350 条量级。
- 语料语言中文为主,**不造多语语料**:嵌入模型 bge-m3 具备跨语言检索,中文语料可被英文查询命中;答案语言由 Agent 提示词管,与语料语言无关。

### 摄入管线

- **CLI 脚本**触发,不做事文档上传界面——解析可在离线完成,避免把大文件解析、超时、失败重试变成运行时产品问题。
- 解析用 **`pypdf`** + **自写切块**;拒绝 LlamaIndex(理由见「考虑的选项」)。
- 切块按章节/段落语义切;FAQ 以一问一答为一个知识单元,不切。
- **完整溯源**:文档标识 / 标题 / 来源渠道 / 发布日期 / 章节或页码 / 切块序号——切块级引用与评测判据都依赖它。
- 幂等采用**覆盖 + 语料版本台账**:每份文档一个稳定标识,重灌时同 id 覆盖;另记语料批次(含内容哈希),供评测绑定版本。

### 检索与问答面

- **不新增业务域**:新增一个**统一检索工具**(一次查 `faq` + `market_intel` 两集合),**只暴露给客服域**;现有 `faq_search` / `trend_query` / `competitor_analysis` 三工具原样不动,避免同集合出现两条工具路径导致模型选择不确定。
- 答案带**切块级引用小点**(上标数字,同一文档多次引用合并编号),**内嵌现有答案面**,不建独立视图;引用数据随回答一起下发,前端自足。
- 引用覆盖范围**仅限"有检索依据"的答案**(客服草稿 / 趋势 / 竞品 / 统一检索结果);`scoring` / `sentiment_analysis` / `translate` 等无检索产出的工具不标引用——硬标会逼出造假引用。
- **渲染缝 = 恢复继承基线**:Agent 消息的 Markdown 渲染是**旧系统已验收能力**(旧 `ChatPanel` 经 react-markdown 渲染,用户消息刻意保持纯文本),重建时依赖留在 `package.json` 却**零引用**——属基线回归。本线以此缝为引用渲染的落点,并按验收 A16 把渲染面由旧系统的「驾驶舱会话消息流」扩展至**起草工作台草稿 + 审批中心执行报告**;不透传原始 HTML(无 XSS 面),**不引入 `rehype-raw`**;实现期(#47)按真实产出实测增开 `remark-gfm`(见修订记录),HTML 仍不透传。
- **引用不做图级硬约束**:B12「查证优先」拦的是**流程事实**(有没有查证),而引用标记是**文本产物格式**;图级拦"格式没写对"会让"有据但没标"的答案被误杀,代价大于收益。格式不合规由评测暴露。

### 评测对接

- 引用质量进评测线(#45):用户裁决以 **LLM-as-judge** 评「引用是否支撑答案」;**机械防伪引**(答案引用的切块标识是否真在本次检索命中集内)作为附加判据——judge 对"引用了不存在的编号"这类幻觉不可靠,机械校验近零成本。
- 评测跑批记录当此语料批次标识,使历史分数可归因到语料版本(真实语料会更新,不绑版本则纵向对比从第一天起就是坏的)。

## 考虑的选项

- **RAG 框架**:LlamaIndex 全量 / LlamaIndex 仅摄入部分 / pypdf + langchain 切块器 / **pypdf + 自写切块** —— 选最后一项,四条依据:①LlamaIndex 的 PDF 读取器 `llama-index-readers-file` 底层就是 `pypdf<7,>=6.1.3`,**省不掉解析库**;②`llama-index-core` 基础依赖 **29 个**(含 nltk / numpy / pillow / tiktoken / networkx / tinytag),且依赖 `llama-index-workflows`——LlamaIndex 自己的 agent/workflow 引擎,与本仓 LangGraph 编排**并存两套模型**(ADR-0005 弃用 CrewAI 的理由之一正是框架集成与行为控制);③它最值钱的 `VectorStoreIndex` / `QueryEngine` / `Retriever` 与本仓既有的 `VectorRepository` + `MilvusVectorRepository`(带「写入立即可查」契约测试)+ `EmbeddingService` **重复**,是替换而非补充;④本仓切块策略是定制的(语义切 + FAQ 不切),通用 `SentenceSplitter` 不合身。
- **语料来源**:全自造 / 全真实公开 / **混合** —— 选混合:市场情报侧的公开报告真实存在且质量高(已实测取得 PDF 字节),无自造必要;FAQ 侧公开渠道方向不对,自造是现实路径。
- **可见面落位**:第五主视图 / **内嵌现有答案的引用小点** —— 选内嵌:知识问答的价值发生在「Agent 正在回答」的那一刻,独立检索页是另一种心流;内嵌不动导航与视图结构。
- **问答面归属**:新增第 4 业务域 / **不新增域、新增统一工具** —— 选后者:ADR-0005 明文「版图不变……不扩展财务/营销/合规/报表域」,新增域等于修订宪章核心约束;统一工具 + 只给客服域已满足需求。
- **摄入触发**:CLI / 前端上传 / 两者 —— 选 CLI,理由同「摄入管线」首条。
- **语料更新语义**:清空重灌 / 累积版本 / **覆盖 + 版本台账** —— 选覆盖 + 台账:累积版本会让检索多一层失效过滤且存储翻倍,清空重灌则丢掉了评测绑定版本的能力。

## 后果

- **迁移**:补切块溯源字段与语料批次台账(现有 `market_intel.source` 为 `String(40)`,装不下真实报告名/URL;两表均无自然键,不补则重灌产生重复行)。
- **ADR-0005 正文两处由本 ADR 修订**:技术栈节「当前量级 ≈350 条×1024 维」的陈述(语料重建后失效)、前端节的能力描述(补答案引用);修订行 **D12** 记于 ADR-0005 修订表。
- **既有 Agent 提示词要改**(教它们产带引用的答案),会影响 `test_subgraphs` 等既有断言,须一并更新。
- **验收基线升级**:A3 / A10 由「退化通过」转为「有据通过」;新增知识库与引用两个场景行(B27 / B28);**补 A16** 记账 Markdown 渲染这一基线回归(渲染面扩展至起草台与执行报告)。
- **边界风险**:统一工具只给客服域,选品域仍走其专用工具——若日后出现「选品也要查 FAQ」的诉求,是**新增决策**而非既有能力延伸,须另立 ADR,不得静默扩张暴露面。
- 评测线(#45)保持独立,等本线落地后再开 spec——评测与能力解耦,避免评测面被实现进度绑架。
