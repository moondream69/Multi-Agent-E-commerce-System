# 日常运营增强:数据台(只读视图)与汇率可见面

## 背景

2026-09-12 走查对「UI 是否符合跨境运营日常使用」的判定(#31-#33 会话):UI 符合 ADR-0005 的 Agent 编排控制台定位,但存在日常运营缺口——**商品/订单无只读视图**(盘货/对账只能对话问 Agent,实测单次 40~90 秒并消耗 LLM 预算);**汇率折算口径无可见面**(成交额以 CNY 快照口径聚合,运营看不到当期汇率,信任成本只靠 fx_missing 通知事后兜底)。

本 ADR 按「走 ADR 追加决策」流程新建:**修订 ADR-0005 的前端与版图边界**(三视图表述、报表轻量聚合口径)。业务三域版图不变:选品/订单/客服三业务 Agent 不扩展,数据台仅为既有域的**只读视图层**。

## 决策

### 数据台(第四主视图)

- 导航增至**四视图:驾驶舱 / 数据台 / 起草工作台 / 审批中心**(ADR-0005「三视图」表述由本 ADR 修订,术语回收见 `CONTEXT.md`「四视图」词条)。
- 数据台 = **商品列表 + 订单列表**,**纯只读**:不含上架/下架/改价/删除/流转/取消等任何写操作——一切对外状态变更仍走对话 + 审批护栏,「操作经 Agent」的产品立场不变。
- 每行提供**「问 Agent」跳转**:跳转驾驶舱并预填 Manager 输入(携该行商品/订单上下文),**不代发**,由运营确认后提交。
- 列表的筛选/排序/分页与列集由实现期 spec 定;数据源为只读端点(商品沿用 `GET /api/products`;订单列表端点新增)。

### 汇率卡片

- 驾驶舱新增**独立汇率卡片**:当期汇率(基准 CNY)+ **近 N 日走势** + 缓存时刻;`fx_missing` 场景显「待核」态。
- 走势数据源由 spec 期定:优先外部汇率 API 时序端点(上游支持时),兜底**订单快照时序点**(真实成交口径,零新增外部依赖)。

## 考虑的选项

- **数据视图落位**:驾驶舱内并列面板 / **第四主视图** / 分散展开 —— 选第四视图:盘货与指挥对话是两种心流,并列互相污染;独立视图语义最清晰。代价:「三视图」表述全量改口径,已在同一改动内回收(CONTEXT 词条 + 验收 + ADR-0005 修订表 D11)。
- **交互边界**:纯只读 / **只读 + 跳转对话** / 允许草稿级编辑 —— 选只读 + 跳转:保留 Agent 立场的同时给运营快捷路径;**明确拒绝编辑**(等于无声开回传统后台,预期会生长为「为什么不支持直接上架」,属产品立场问题而非功能欠缺)。
- **汇率形态**:快照条常驻一格 / **独立卡片 + 走势** —— 选卡片:成交额是货币口径,信任需要「当期值 + 变化方向」;走势是运营判断换汇时机的真实需求,非装饰。独立卡片是与数据台同批的可见面投资。
- **实施排期**:**随 UI 第二批一并**(2026-09-12 决定,先 spec 后实现)——与前端重绘同一次动工,减少往返。

## 后果

- 前端四视图;新增只读端点(订单列表)与汇率时序数据面;验收新增 B24(数据台)/ B25(汇率卡片)。
- **边界风险**:「数据台为何不能编辑」将成为高频疑问——只读边界写入本 ADR;**后续任何编辑诉求须另立 ADR,不得静默扩张**。
- 汇率卡片依赖外部汇率 API 的时序能力(或订单快照兜底),上游不可用时的降级路径由 spec 定(沿用「不拒单、如实标注」的既有降级原则)。
- ADR-0005 三视图/版图表述由本 ADR 修订,修订行 D11 记于 ADR-0005 修订表。
