# 全量推翻重写:真实生产定位与新目标架构

## 背景

2026-09-07/08 五轮访谈(业务/架构/协作/行为控制/前端)确认 42 项决策:项目定位从「学习练习」(ADR-0001)转正为**真实生产工具**(2-5 人跨境卖家团队、局域网部署),并决定**推翻式重写**。推翻理由(访谈 Q14,四项全认):ReAct 控制力不足(工具强制靠补丁)、基础设施欠账(单 worker 硬约束、进程内轮询审批、会话无历史)、EventBus 隐式耦合(跨 Agent 数据流难追踪)、学习练习时代代码质量。

旧系统冻结原地重写(重写期间演练环境不可用);业务决策是唯一约束;旧系统已验收场景集 = 新系统验收基线(见 `docs/acceptance-scenarios.md`)。

## 决策

### 文档边界(2026-09-12 裁定,issue #23)

- **职责**:本 ADR = **业务决策的唯一约束**(兼架构依据);`CONTEXT.md` = 目标态术语与语义口径的真源;`docs/acceptance-scenarios.md` = 验收基线。
- **冲突裁决**:同一事项两边表述不一致时——涉及「做什么/不做什么」的**决策**,以本 ADR 为准;涉及**术语、命名、语义细节**,以 `CONTEXT.md` 为准。无论哪一侧胜出,**须在同一次改动内把另一侧回收为一致表述**,并在本 ADR 文末修订记录留痕,不得两处各说各话。
- **偏差回收标准动作**(替代「只记账不改正文」的旧先例):①改写正文;②同步升级对应验收清单行;③issue 留痕。三者缺一不可——只记账不升级等于留下假信息。

### 技术栈

- **协作与控制:纯 LangGraph 全栈**。团队协作 = supervisor 模式(Manager + 3 业务 Agent 子图);单 Agent 行为控制 = 子图内动态工具暴露 + 图级边约束;人类审批 = `interrupt`(durable,PostgresSaver);观测 = Langfuse 自托管。
  - 弃用 **CrewAI**:查证无 LangGraph 原生集成、可靠性审计(SIGKILL 后重执行)与基础设施欠账痛点同向、Agent 内部循环自主与「精确行为控制」意图相反。
  - 弃用 **LangSmith**:自托管=企业许可+已废弃 Docker 部署(仅剩 K8s);云版=代理+生产数据出境。选 **Langfuse** 自托管(开源、Docker Compose、trace/evals、零出网依赖)。
- **向量库:Milvus Standalone**(Docker,跑现有 WSL 环境,不改动 WSL 配置);访问抽成向量仓库接口,pgvector 实现可切换(当前量级 ≈350 条×1024 维,接口抽象保切换退路)。
- **保留**:PostgreSQL、Redis(LLM 限流+短时状态)、socket.io(事件流形态,语义重设计)、React+Vite+TypeScript、DeepSeek v4 Flash(统一模型)、Ollama bge-m3(1024 维)、uv。

### 协作架构

- **Manager(supervisor)**:零写权限 + 只读查询(指挥不亲自动手);规划时声明子任务依赖,独立子任务并行扇出、依赖串行;规划步数上限 5。前端以第 4 角色可见(规划/分派轨迹透明)。
- **会话记忆**:短上下文(最近 **6 条消息**,≈3 轮往返)+ 超窗摘要(消息数 > **12** 条触发 LLM 压缩);不做长期记忆(ADR-0004 轻量边界升级)。定值为实现期裁定(`core/memory.py` 常量),改口径须四处同步:本行 / `CONTEXT.md`「会话」词条 / 验收 B16 行 / 常量。
- **thread 粒度**:一次用户请求(含 Manager 流水线)= 一个 thread;会话 = thread 容器。请求级恢复,不重放会话。
- **自动数据流**:报告→自动草稿 = 子图内工具调用(A4 工具化:`generate_report` 后由选品 Agent 调 `draft_create` 免审直行);订单变更→主动通知 = apply/REST 在**事务提交后**按效果描述组装并广播。事件通道为**单向广播面**(`EventEmitter` → WS 实况),**不建事件触发层**。
- **通知文案**:状态映射表机制沿用(零 LLM 成本);文案为卖家运营口吻(2026-09-11 起,原买家口吻「您的订单 #N…」已改)。
- **IntentParser** 关键词规则降级为 Manager 的 fallback 安全网(LLM 失败时确定性路由兜底)。
- **并发模型**:单进程 asyncio + thread_id 隔离;LLM 并发闸 2 保留(DeepSeek 账号级限流防护)。

### 行为控制

- **工具暴露**:节点级动态绑定——LLM 看不到未授权工具;图级边约束拒绝非法迁移。约束前移到 LLM 看见工具之前。
- **风险三层分类**:免审(draft 内部编辑)/ 审批(一切对外状态变更:上架/下架/改价/删除/订单流转/取消)/ 禁做(不暴露)。
- **切片式人工环节**:Manager 规划时按人工断点将任务切分为切片;切片内高危写动作按类型打包为审批单(批内同进同退);切片边界 `interrupt` 挂起(状态落库、协程释放、可跨重启恢复);审批通过后**用户指令驱动** resume(按钮+自然消息双入口);切片被拒 → Manager 携拒绝原因重规划(跳过/替代路径/终止)。
- **失败语义**:分层——LLM 调用瞬时错误(429/5xx/网络)本地重试 1-2 次(退避 1s/2s),工具执行失败以观察结果回喂 LLM(由 LLM 决定改道或如实作答);仍败在**子图边界收敛**:切片如实产出「未完成+原因」,任务标 `failed` 并广播 `task.failed`,**不触发重规划**(重规划仅由人工拒绝触发);永不静默吞错。边界:编程错误(非 LLM 失败)兜底收敛后仍**原样上抛 500**(观测保留);辅助簿记(记忆/广播/计划刷新)失败只记日志——日志可观测即不算静默吞错。LLM 输出校验重试上限 2。
- **影子模式**:环境级配置(演练环境开影子、生产环境锁审批,生产运行时不可切换)。
- **客服强制工作流**:查证优先硬约束——出草稿前必调 faq_search/order_lookup,禁止凭空作答;取代 ADR-0002 两阶段(情感分析降级为可选工具)。
- **步数上限**:业务 Agent 子图 10 步、Manager 规划 5 步,超限强制终止并产出「未完成+原因」。

### 业务强化(访谈第 1 轮)

- **真实库存**:products 加 stock 字段、REST 下单扣减、check_inventory 改读库(消除 LLM 自报库存)。
- **升级工单实体化**:tickets 表落库 + 界面可见列表(升级不再是断头事件)。
- **数据入口**:CSV 批量导入(商品/订单/买家;**买家先于订单**,订单按 email 解析买家)+ Agent 对话创建;下单另有需认证的 REST 端点 `POST /api/orders`(模拟流量入口)。真实数据导入后 seed 假数据降级为演练库资产。
- **币种**:实时汇率 API,汇率快照随订单落库(基准 CNY,Redis 缓存 4h);API 失效**先降级用最近缓存**,缓存亦空则**留空落库** + `fx_missing` 通知(人工核对),**不拒单**。
- **客服 Agent 重定位**:多语言起草助手——真人贴入买家消息 → 多语草稿 → 人工修改发出;买家侧保持模拟(不接真实渠道)。
- **版图不变**:选品/订单/客服三业务 Agent(不扩展财务/营销/合规/报表域;报表做轻量聚合视图 + 只读数据视图(ADR-0006:数据台/汇率卡片,均为既有域的只读面,不新增业务域))。
- **单平台起步**:platform 字段保留为标记,多平台矩阵留待后续 ADR。
- **里程碑**:验收场景清单全绿 → 真实试运行 → 生产切换。

### 前端

- **四视图重构**:驾驶舱(协作管线 + Manager 第 4 角色 + 切片时间线 + 事件流实况墙 + 汇率卡片)、**数据台**(商品/订单只读列表 + 行级「问 Agent」跳转;ADR-0006)、客服起草工作台(双栏:左买家消息+查询证据、右可编辑草稿+一键复制)、切片式审批中心(审批单携带任务上下文+后续计划预览;影子段仅演练环境显示)。
- **切片视图主时间线**:段状态(完成/等待审批/待执行)+ 断点审批入口 + 重规划事件;StepsTimeline 降为段内工具细节。
- **通知铃铛**保留(**服务端按用户已读**,多端一致;面板内按 kind 分组;旧「localStorage 未读」「按 Agent 归卡」语义已下线);多会话机制保留;登录平权无角色保留。

### 部署

- 全容器 docker compose 一揽子:PostgreSQL + Milvus + Langfuse + Redis + app;跑现有 WSL Docker,不改动 WSL 环境。
- **前端静态托管未落地**:生产托管形态未定,当前仅开发态 Vite(5173,`/api` 与 `/socket.io` 代理到 3000),compose 无前端服务;落地后回收本行。

## 被修订/取代的既有决策

- **ADR-0001**:学习练习性质退役,定位转正为真实生产工具。
- **ADR-0002**:两阶段强制(阶段1 必调情感分析+FAQ)由「查证优先硬约束」取代。
- **ADR-0003**:演示冲刺现状由本次重写覆盖;买家前台维持移除、事件接线语义随新架构重设计。
- **ADR-0004**:会话记忆升级(短上下文+摘要);多会话 UI/历史隔离保留为验收场景。
- **issue #3(批量审批串行阻塞)**:由切片式人工环节 + 批内打包审批 + durable interrupt 架构级根治(旧系统冻结,不再单独修复)。

## 考虑的选项

- **演进式 vs 推翻式**:资产盘点显示系统无真实生产数据(seed 全为 LLM 假数据、真实入口未建),数据迁移成本≈0;42 项业务决策已钉死「做什么」,推翻式 = 把已确认的业务形态用更合理的架构重做一遍,风险可控。
- **CrewAI+LangGraph 双框架**:见上,弃用。
- **Milvus vs pgvector**:当前量级 pgvector 足够,但学习价值 + 未来扩展考虑选 Milvus,接口抽象保退路。
- **任务级批次 vs 逐动作审批**:批量打包 + durable interrupt 同时解决资源阻塞与交互风暴;逐动作制造 N 次挂起/N 次决定。

## 后果

- 旧系统冻结原地重写,期间演练环境不可用;新旧不并行。
- 前端契约(types/events.ts 真源)与表结构随推翻重设计,事件清单语义随落地文档定。
- 验收基线:`docs/acceptance-scenarios.md`(继承场景=旧系统已验收集;新增场景=切片/打包/CSV/起草台/durable 恢复等)。
- CONTEXT.md 重写为目标态术语表(Manager/切片/thread/审批批次/起草助手等)。
- 运维组件从 3 增至 6,docker compose 一揽子管理;Langfuse 观测数据不出局域网。
